# Саммаризация стенограммы созвона

## Основная информация о проекте

- **Заказчик**: Клиентский сервис. Бюджет контролирует digital-направление IT, отвечающее за продукты, приносящие прибыль (мобильные приложения, сайт, киоск и т.д.)
- **Директор ИИ**: Сергей Черетин (ранее был директором Digital)
- **Статус тендера**: Сейчас проводится первый тендер. После него планируется продолжить работу с текущим поставщиком на некоторое время, а затем провести второй тендер для выбора долгосрочного партнера.
- **Текущий вендор**: Яндекс
- **Бюджет**: Не определен конкретно, но явно меньше 100 млн рублей (компания, предложившая такую сумму, была отсеяна)

## Требования к чат-боту

### Технические параметры
- **Нагрузка**: 180-200 тысяч обращений/диалогов в месяц, пиковые нагрузки до 280 тысяч (декабрь)
- **Интеграции**: До 15 API-интеграций, включая:
  - Система Helpdesk
  - Панель администрирования мобильного приложения
  - Система лояльности клиентов

### Функциональность
- Основной приоритет: взаимодействие с пользователями
- В первую очередь: обработка обращений пользователей, консультации клиентов
- Опционально: маркетинговые активности, база знаний для сотрудников (отдел персонала, юридическая служба)
- Планируется выделить MVP-функционал (предположительно к июню)

### Технологический подход
- Текущее решение использует TF + логистическая регрессия (классические ML-методы)
- Обсуждались варианты:
  1. Решение на базе классических методов (работает на CPU)
  2. LLM + RAG с построением графа знаний (требует GPU)
  3. Гибридный подход: классические методы для большинства запросов, LLM для сложных случаев

- Текущая эффективность бота: около 70% успешных обработок запросов

## Сроки и следующие шаги

1. **Первый тендер**: Текущий месяц - следующий месяц
2. **Контракт с текущим поставщиком**: До конца 2024 года
3. **Второй тендер**: Предположительно в 2025 году (Q3)
4. **Внедрение новой системы**: Примерно в 2026 году

**Зависимости**:
- Внедрение новой Helpdesk-системы планируется к февралю 2026 года (хотя есть сомнения в реалистичности этих сроков)
- Решения тендерного комитета

## Действия исполнителя по итогам созвона

Требуемая информация от заказчика:
- Список систем, с которыми требуется интеграция
- По возможности верхнеуровневая архитектурная схема
- Примеры сценариев диалогов (GNSOC-формат)

## Выводы

1. Заказчик находится на этапе выбора решения для замены текущего чат-бота (Яндекс)
2. Приоритет - сохранить и улучшить текущую функциональность обработки клиентских запросов
3. Возможные технологические решения варьируются от классического ML до LLM+RAG
4. Процесс внедрения будет многоэтапным с переходным периодом
5. Дополнительная информация по срокам и более детальным требованиям будет доступна в июне
6. Необходимо предусмотреть и учесть интеграцию с новой Helpdesk-системой, внедрение которой планируется в будущем
